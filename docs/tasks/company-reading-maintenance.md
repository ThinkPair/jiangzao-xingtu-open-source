# 公司阅读持续维护

2026-11-04，所有者明确要求恢复本机入口、继续更新每家公司内容、建立持续目标，并在一定阶段同步Git。本任务承接这次授权；原云端服务和会员经营继续停止。

## 范围与顺序

先按现有355家公司目录逐家核对新披露，其中工业富联完整拆解保留为只读标杆。每家公司分别记录旧资料期间、新披露是否找到、完成核对还是尚有缺口，不把整个目录日期统一改成今天。现有范围完成后，再按既有冻结公司索引补齐尚未覆盖的生意概览；这个索引是历史范围，不代表实时上市名单。

第一批选择浪潮信息、中科曙光，补2026年第三季度经营变化。其余公司仍处于待核状态。首批两家更新不会增加公司覆盖总数，也不改变旧网站185家概览、14家七问和186家去重可读的历史验收计数。

所有者进一步明确：桌面直接打开原星图，在原项目的公司页内更新内容，不增加中转门户或另一套阅读网站。公司解读与结构化财务数据库各自标明期间；公开Markdown是GitHub阅读副本，不替代原公司页的集成验收。

## 一批怎样完成

1. 取得公司或交易所正式原件，保留披露日、报告期、原始链接和PDF页序。原件与核读证据留在维护工作区，公开仓库只收可公开整理稿和必要资料索引。
2. 先在独立版本包里更新原公司解读的相关问题和来源，沿原内容审批链核验，再装入原公司页。公开的定期经营笔记写入 `docs/companies/updates/<期间>/<公司代码>.md`，登记 `updates/index.json`；这份文档不能单独代表原项目已经更新。
3. 明确区分累计与单季、余额与流量、公司解释与我们的解读。空值不填零，正式季报不写成审计报告，不使用涨幅倒推生意质量，不把算力相关业务全算成AI收入。
4. 由另一审阅者查看原件，核对数字、单位、期间、页码及推断边界。问题修复后再计算该稿指纹。
5. 原应用按批准后的内容构建，在原公司页核验来源、正文和朗读。公开文档执行 `python scripts/sync_reading_updates.py --write` 后用 `--check` 检验一致；核对未修改的问题、历史口径及保护标杆保留。
6. 原应用使用完整运行资料执行内容批准、真实构建及适用的完整校验，再记录本地集成；公开源码副本可用 `app/scripts/update_gate.py code validate --static-only` 检查适用子集。两者凭据分别记录，刷新并校验公开导出清单；静态通过不能代替原应用验收。
7. 每个有独立价值且通过核验的批次提交、同步Git并回读文件/提交。远端若有新修改，先合并核对；不强制覆盖。同步完成才写真实回执，不按定时器无内容提交。

## 持续接手

公开资料索引为 `docs/companies/updates/index.json`；最近维护记录见 `docs/update-log/`。原公司页及 `catalog.json.asOf` 继续表示原稿日期，新增 `latestUpdate` 单独标记报告期、披露日与核对日。

本轮使用独立的持续目标与维护清单。旧云端生产队列、旧小时自动化和原文快照导入链不因本任务而恢复。缺少新原件的公司保持待核，已有内容不自动删除，不虚填已更新。

仓库外旧生成器会覆盖阅读页，不能直接重跑。当前增量脚本只维护带标记的链接区与增量元数据；在合并前检查历史正文是否逐字保留。
